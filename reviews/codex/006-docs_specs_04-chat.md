1. **[high] Tool toggles don’t establish an enforceable permission boundary.**  
   **Reference:** [Context panel and tool rules, lines 15–22](E:/AI/review-loop/junos/docs/specs/04-chat.md:15).  
   **Why it matters:** Selecting a project sets a CLI’s `cwd`, which does not restrict its filesystem access. Official CLI clients may also expose native tools outside the daemon’s “small tool set.” Merely referencing spec 12 leaves open whether Files off actually prevents reads or writes.  
   **Concrete fix:** Require each adapter to enforce the selected tool allowlist and approval policy, including native CLI tools. Fail closed when enforcement is unavailable. Specify that changing projects or toggles applies to subsequent runs and never silently expands an active run’s permissions.

2. **[high] Automatic titles can disclose a conversation to another provider.**  
   **Quote:** “Titles are auto-generated by the cheapest connected model after the first exchange.” [Line 23](E:/AI/review-loop/junos/docs/specs/04-chat.md:23).  
   **Why it matters:** A conversation intentionally sent to one provider may silently reach another for naming. “Cheapest” is also undefined for subscriptions with shared usage caps; spec 03 explicitly treats capacity as a budget.  
   **Concrete fix:** Default to a local title derived from the first user message. Make generated titles optional, use the conversation’s provider, and specify the minimal text transmitted.

3. **[high] Attachments and history replay lack a clear disclosure contract.**  
   **Reference:** [Composer, Context panel, and model switching, lines 10–21](E:/AI/review-loop/junos/docs/specs/04-chat.md:10).  
   **Why it matters:** Folder attachment, project selection, file mentions, and `cwd` imply different access scopes. The spec never states which contents are sent, whether folders expand recursively, or whether switching models forwards old attachments. Spec 11 promises explicit attachment and default secret exclusions; spec 03 additionally permits provider fallback.  
   **Concrete fix:** Define a per-run context manifest showing recipient, included files, exclusions, sizes, and truncation. Apply spec 11’s exclusions to direct attachments too. Distinguish project selection from attachment, snapshot included content, and require explicit authorization before replay or fallback expands provider access.

4. **[high] Rich message rendering has no untrusted-content policy.**  
   **Quote:** “markdown, code blocks with copy, tables … tool-call cards.” [Line 13](E:/AI/review-loop/junos/docs/specs/04-chat.md:13).  
   **Why it matters:** Provider output and tool results are untrusted. Raw HTML, unsafe URL schemes, and remote images could enable script execution, dangerous navigation, or tracking. A markdown imitation of an approval card could also confuse content with trusted controls.  
   **Concrete fix:** Require sanitized markdown, disabled raw HTML, safe link schemes, and blocked remote image loading by default. Render tool and approval controls exclusively from authenticated structured run events, visually distinct from message content.

5. **[high] Streaming defines cancellation but omits recovery and duplicate prevention.**  
   **Reference:** [Streaming and API sketch, lines 14 and 25–30](E:/AI/review-loop/junos/docs/specs/04-chat.md:25).  
   **Why it matters:** A dropped SSE connection does not necessarily stop the provider. Retrying could create a second run or repeat tool side effects. The API sketch supplies neither event resumption nor a conversation-detail endpoint for recovering persisted history, despite spec 01’s restart guarantees.  
   **Concrete fix:** Specify run/message IDs, idempotent submission, ordered event IDs, reconnect/replay, and history retrieval. Distinguish completed, cancelled, failed, and interrupted output. Define whether cancellation stops queued tool calls and when cancellation is considered confirmed.

6. **[med] Phase boundaries contradict the roadmap and understate delivery scope.**  
   **Reference:** [Features and Phase 1 acceptance criteria](E:/AI/review-loop/junos/docs/specs/04-chat.md:9).  
   **Why it matters:** Compare is labelled Phase 3 here but Phase 4 in spec 13. Tasks, Kanban, Hermes, and indexed file mentions appear without phase labels despite arriving in later phases. Phase 1 acceptance checks Claude only, while the roadmap requires Claude and Codex, fallback, and persisted history.  
   **Concrete fix:** Assign every feature a phase matching spec 13. Expand Phase 1 acceptance to both adapters, history after restart, fallback attribution, and interrupted-run recovery. Explicitly defer unavailable integrations.

7. **[med] Retry and branching have no conversation semantics.**  
   **Quote:** “retry with another model, branch from this message”; “history is replayed as plain messages.” [Lines 13–21](E:/AI/review-loop/junos/docs/specs/04-chat.md:13).  
   **Why it matters:** Spec 02 has no explicit parent-message or branch relationship. It is unclear whether retries replace answers, which answer subsequent messages follow, or how tool results and cancelled output enter replay. Flattening everything risks losing provenance or treating untrusted tool text as ordinary instructions.  
   **Concrete fix:** Define retry as an alternative run and branch as a new conversation referencing an immutable prefix, or specify an explicit message tree. Define replay roles, attachment handling, context-limit behavior, and exclusion of private reasoning and incomplete tool exchanges.

8. **[med] Capability handling stops at effort levels.**  
   **Reference:** [Model picker, effort picker, and messages, lines 11–15](E:/AI/review-loop/junos/docs/specs/04-chat.md:11).  
   **Why it matters:** Different adapters may support different attachments, tools, reasoning summaries, and context sizes. “Collapsible thinking” reads as universal. Switching models can leave an unsupported effort selected; current `src/lib/providers.ts` supplies model names without capability metadata.  
   **Concrete fix:** Require capability metadata per model/adapter. Revalidate effort and attachments on model change, explain unavailable controls, and show reasoning summaries only when explicitly emitted. Label token counts as estimates with a model-specific context limit.

9. **[med] The three-column layout has no minimum-width or collapse policy.**  
   **Quote:** “Left … Center … Right (collapsible).” [Line 7](E:/AI/review-loop/junos/docs/specs/04-chat.md:7).  
   **Why it matters:** The Stitch prompt proposes 260px and 300px side panels, while spec 14 specifies 360–420px drawers. At ordinary laptop widths, these plus the global rail squeeze the thread well before the shared 900px breakpoint. Code and tables make the conflict worse.  
   **Concrete fix:** Resolve panel widths in this document, set a minimum usable thread width, and auto-collapse Context before violating it. Specify conversation navigation and Context as sheets on narrow screens, with horizontal overflow confined to code and tables.

10. **[med] Message hierarchy and typography are left to generic chat defaults.**  
    **Reference:** [Layout and Messages](E:/AI/review-loop/junos/docs/specs/04-chat.md:6).  
    **Why it matters:** Every response potentially adds model, effort, route, reasoning, tools, and four actions without an emphasis order. The existing `.bubble` styling uses a generic rounded-panel pattern and prominent accent-filled user messages. Nothing here directs the implementation toward a readable working thread.  
    **Concrete fix:** Make response content primary, provenance a compact secondary line, and occasional actions an overflow menu. Adopt spec 14’s 760px maximum reading width; define body size/leading, paragraph spacing, turn spacing, and code typography. Preserve the chosen glass identity in shell surfaces while keeping message bodies quiet and tool details collapsed.

11. **[med] Keyboard and streaming accessibility are underspecified.**  
    **Quote:** “Enter to send, Shift+Enter newline”; unsupported efforts are “greyed.” [Lines 10–12](E:/AI/review-loop/junos/docs/specs/04-chat.md:10).  
    **Why it matters:** Enter can submit during IME composition or select an autocomplete item. Disabled styling alone does not explain unavailable efforts. The spec omits picker navigation, focus restoration, streaming announcements, and scroll behavior; spec 14 delegates screen-specific keyboard rules to each spec.  
    **Concrete fix:** Suppress sending during composition and autocomplete selection. Define accessible picker/segmented-control semantics, Escape behavior, labelled controls, and focus return. Announce run states without reading every token; preserve the reader’s scroll position and offer “Jump to latest.”

12. **[med] Agent mentions blur conversation with delegation.**  
    **Reference:** [Composer and slash commands, lines 10–17](E:/AI/review-loop/junos/docs/specs/04-chat.md:10).  
    **Why it matters:** Spec 07 says `@agent` hands off a message, while `/hermes` also issues directives. The spec does not establish what context transfers, how delegation is shown before sending, or whether cancelling the chat stops the delegated work. A badge alone cannot communicate that a message launches autonomous activity.  
    **Concrete fix:** Represent delegation as an explicit composer chip naming the recipient and context. Distinguish asking an agent from issuing a directive. Link the resulting run, expose its approval and execution state, and define cancellation propagation.
