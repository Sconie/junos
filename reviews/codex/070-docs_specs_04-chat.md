1. **[high] Chat’s tool toggles do not define an enforceable security boundary.**  
   **Reference:** §Features, “tool toggles”; §Behavior rules, tools “always behind the approval policy in 12.”  
   **Why it matters:** Providers run through official CLI clients (01, 03), which may have their own tools and permissions. Restricting daemon tools alone does not establish that Files-off prevents CLI file access or that native CLI actions wait for JunOS approval. Selecting `cwd` also grants context whose boundaries are unspecified.  
   **Concrete fix:** Require each adapter to enforce the selected file scope and tool policy, including native tools. Fail closed where interception is unsupported. Define how chat shows a pending approval, denial, and timeout before enabling tool execution.

2. **[high] Automatic title generation can disclose a conversation to an unexpected provider.**  
   **Quote:** “Titles are auto-generated by the cheapest connected model after the first exchange.”  
   **Why it matters:** A conversation deliberately sent to one provider could silently be sent to another for naming. “Cheapest” also lacks a defined meaning for subscription routes with shared usage caps (03).  
   **Concrete fix:** Default to a local title derived from the first user message. Make generated titles optional, use the conversation’s selected provider, and specify the limited text supplied. Title-generation failure must not interrupt chat.

3. **[high] Switching models lacks a disclosure and context-transfer contract.**  
   **Quote:** “Switching model mid-thread is allowed; history is replayed as plain messages.”  
   **Why it matters:** This can transmit previously attached private content to a new provider. Plain replay also leaves tool results, cancelled answers, agent replies, and context-window overflow ambiguous. Routing fallback in 03 creates the same risk automatically.  
   **Concrete fix:** Define exactly which messages and attachments transfer, exclude internal reasoning, preserve provenance, and show the destination before a cross-provider transfer. Specify truncation or summarisation behavior and require explicit opt-in for cross-provider fallback.

4. **[high] Attaching a project folder has no bounded meaning.**  
   **Reference:** §Composer, “attach files or project folders”; §Context panel, selected project sets `cwd`.  
   **Why it matters:** Attaching a folder, mentioning a project, and granting working-directory access are different permissions. Although 11 defines indexing exclusions, 04 does not say those exclusions apply to attachment expansion or CLI reads. A folder could include secrets, excessive content, or links outside its apparent scope.  
   **Concrete fix:** Distinguish “use as working directory” from “send selected contents.” Require a preview of included files, exclusions, destination provider, and size/token limits; enforce allowlists, secret exclusions, and canonical path checks in the daemon. Define whether attachments are snapshots or reread on every turn.

5. **[high] Rich message rendering lacks a trust policy.**  
   **Quote:** “markdown, code blocks with copy, tables, collapsible thinking, tool-call cards.”  
   **Why it matters:** Moving from the current plain-text rendering in `src/pages/Chat.tsx` to rich output introduces an untrusted-content boundary. Raw HTML, unsafe links, and remotely loaded images could execute unwanted behavior or disclose that a private message was viewed.  
   **Concrete fix:** Specify sanitised Markdown with raw HTML disabled, permitted URL schemes, and remote media blocked until requested. Tool cards must use structured adapter events rather than model-authored markup. Show reasoning summaries only when the adapter explicitly supplies them; support an unavailable state.

6. **[high] Cancel and reconnect behavior can leave the transcript inconsistent with execution.**  
   **Reference:** §Streaming, “Partial output is kept on cancel”; §API sketch, message POST streams SSE.  
   **Why it matters:** There is no definition of when the run/message is durably created, how its ID reaches the client, how a dropped stream reconnects, or whether repeating a POST duplicates a run. Stopping visible output is also different from stopping CLI tools or handed-off agents.  
   **Concrete fix:** Define durable IDs, idempotent submission, an authenticated resumable event stream, and terminal states. Mark partial messages as cancelled or interrupted. Show “Stopping…” until termination is confirmed, and state which child work is cancelled and which side effects already occurred.

7. **[med] The Phase 1 boundary is unclear and contradicts the roadmap.**  
   **Reference:** §Features; “Compare mode (phase 3)”; §Acceptance criteria.  
   **Why it matters:** Only compare is phase-labelled, leaving branching, folder attachments, agent mentions, scheduling, and Kanban actions apparently in the initial feature set. Roadmap 13 places automation in Phase 2, agents/board in Phase 3, and compare in **Phase 4**. Acceptance tests cover Claude only, while roadmap Phase 1 requires Claude and Codex.  
   **Concrete fix:** Label every capability by phase and dependency. Align compare with the roadmap. Add Phase 1 acceptance for both providers, persistence after restart, cancellation, unsupported effort levels, fallback, and failed-stream recovery.

8. **[med] Retry and branching have no transcript semantics.**  
   **Quote:** “retry with another model, branch from this message.”  
   **Why it matters:** The flat conversation/message schema in 02 has no explicit parent or alternative-response relationship. Implementations could overwrite an answer, replay the wrong context, or hide which response later turns reference.  
   **Concrete fix:** Define retry as a preserved alternative with a new run, and branch as a new conversation with a source-message reference and an immutable copied prefix. Specify attachment inheritance and which answer becomes active for subsequent turns.

9. **[med] The three-pane layout has no workable width budget.**  
   **Reference:** §Layout, “matches mockup.”  
   **Why it matters:** The Stitch prompt specifies a 260px conversation list and 300px context pane, while 14 specifies 360–420px drawers. At 1024px, a 64px rail, 260px list, and 360px context pane leave only 340px before gutters. The shared 900px breakpoint does not resolve this cramped intermediate layout.  
   **Concrete fix:** Declare the authoritative pane dimensions, a minimum thread width, and collapse order. Close Context first, then turn conversations into a drawer when the thread cannot fit. Define narrow-screen list → thread → context navigation, including back behavior and scroll preservation.

10. **[med] Message hierarchy, typography, and action density are unspecified.**  
    **Reference:** §Messages lists metadata, rich content, and numerous actions without placement or sizing.  
    **Why it matters:** Model/effort/route labels, thinking, tools, and actions could compete with the answer. The current `.bubble { max-width: 70% }` in `src/index.css` would further squeeze code and tables inside a narrow thread. The shared 760px maximum does not establish reading rhythm.  
    **Concrete fix:** Specify a starting scale: 16px answer text at roughly 1.55 line height, 12–13px metadata, 14px code, and consistent 24–32px turn spacing. Align answers and composer to one readable column. Keep Copy visible, group secondary actions in a keyboard-accessible menu, and give wide code/tables their own horizontal scrolling.

11. **[med] Glass execution lacks chat-specific contrast and layer rules.**  
    **Reference:** §Layout/Features; inherited glass tokens and accessibility requirements in 14.  
    **Why it matters:** The shared spec already requires contrast and fallbacks, but 04 does not assign surfaces to the thread, composer, tool cards, and popovers. These elements can easily accumulate blur layers or put small labels over variable glow. Light text `#E7E8EC` on solid violet `#8B5CF6` measures only **3.46:1**.  
    **Concrete fix:** Define a chat surface map, keeping atmospheric glass on major panels and stronger backing behind text-heavy overlays. Test composited backgrounds, code highlighting, selection, focus, and disabled states. A viable alternative accent is the existing blue `#7C9CFF`: dark ink `#0B0C0F` on its solid fill measures **7.50:1**, and blue text on `#16181F` measures **6.80:1**. It also separates interaction from teal health indicators. Verify actual glass composites and provide an explicit opaque preference.

12. **[med] Streaming motion and scrolling behavior are missing.**  
    **Reference:** §Streaming; collapsible thinking/tool cards; inherited reduced-motion requirement in 14.  
    **Why it matters:** Token updates, expanding cards, and automatic scrolling can continuously move the reading target. A general reduced-motion rule does not explain how this chat behaves while someone reads earlier messages.  
    **Concrete fix:** Follow output only while the reader is near the bottom; otherwise preserve position and show “New output.” Avoid per-token entrance effects, batch visual updates and assistive announcements, and specify reduced-motion behavior for disclosures and activity indicators. Keep decorative glow static during reading.

13. **[med] Composer and picker interactions are not sufficiently defined for keyboard use.**  
    **Reference:** §Composer, “Enter to send”; §Model picker, “disabled providers show a Connect link”; §Effort picker, “greyed.”  
    **Why it matters:** Enter can accidentally submit during input-method composition or autocomplete selection. A Connect link inside a disabled option may be unreachable. Greying unsupported effort levels does not explain the current valid choice.  
    **Concrete fix:** Define Enter precedence for IME, `/`, and `@` menus; retain drafts across navigation and errors. Give Connect an independently focusable action. Specify labelled picker controls, arrow-key navigation, Escape/focus restoration, and visible explanations for unavailable efforts. Validate and reset effort when the model changes.

14. **[med] Agent mentions blur reference, delegation, and cancellation.**  
    **Reference:** §Composer, `@agent`; §Slash commands, `/hermes`; agent badge in §Purpose.  
    **Why it matters:** In 07, mentioning an agent actually hands it a message. Ordinary mention syntax therefore initiates work, but 04 does not define which context is shared, where progress appears, or whether switching the model affects the agent. A badge alone cannot explain those differences.  
    **Concrete fix:** Make delegation explicit in the autocomplete and composer, show the context being handed over, and attach the resulting directive/run to the thread. Define model-picker ownership and cancellation behavior for agent conversations. `/task` should similarly open a reviewable schedule draft before enabling recurring execution.
