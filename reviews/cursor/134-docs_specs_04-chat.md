**Verdict:** As an Operate / app-screen brief, `04-chat.md` is a feature inventory with a three-column wireframe — not a designable chat surface. Hierarchy, density, states, motion, a11y, and privacy edges are mostly unspecified; chrome and message actions are overloaded for Phase 1.

Lens: Impeccable **Operate** + design-taste **app screens**. Doc-only (no rendered UI). The brief pins “matches mockup” without locking type, color, density, or states.

---

### Contradictions

1. **Same component vs separate product surfaces** — Purpose says agent chats “live in the same component with an agent badge (see 07)”. Layout and Features describe a model/effort/composer chat. One screen cannot be both “any connected model” and Hermes mission-control without clarifying what is shared (shell only) vs what is mode-switched (thread chrome, tools, badges).

2. **“Matches mockup” with no visual contract** — Layout claims mockup parity, but the doc never states density, type scale, surface treatment, or whether glass/violet chrome from the design set is in scope. Implementers will invent a second look or copy Stitch tells (glass, accent on chrome) that app-screen house rules ban.

3. **Effort “greyed” vs legible disabled** — “greyed where the model has no such level” fights Operate/app-screen rules: disabled must stay readable and say *why*. Greying alone fails contrast and teaches nothing.

4. **Phase 1 acceptance vs feature list** — Acceptance is send / change model·effort / logged-out Connect. Features still list `/` commands, `@` mentions, folder attach, tool-call cards, branch, “send to Kanban”, “save to file”, Context tool toggles, and Compare (phase 3). Unclear what ships in Phase 1 vs later.

5. **Local storage vs title generation** — “Conversations are stored locally” sits next to “Titles are auto-generated by the cheapest connected model after the first exchange.” Local UI storage does not mean content stays local; titles imply sending thread text off-box.

### Unrealistic scope

For a Phase 1 “send + stream + pickers” bar, the Features section packs a full IDE chat:

- Folder attach + `@` file/project/agent  
- Slash surface that reaches Tasks, Kanban cards, Hermes directives  
- Tool-call cards + collapsible thinking + branch + Kanban + save  
- Context tool toggles (Files, Web, Hermes, Tasks)  
- Compare mode (even if phase 3, it sits in the same Features block)

That is several products in one composer. Cognitive load: visible decision points already exceed four (model, effort, tools, attach, commands) before the user types. Distill Phase 1 to: list, thread, composer, model, effort, stream/cancel, logged-out Connect — move the rest to named later phases with UI stubs, not full behaviors.

### Security / privacy risks (called out by the doc’s own claims)

1. **Title generation** — Cheapest connected model sees first-exchange content; no consent, redaction, offline/local-title option, or “don’t send for titles.”
2. **Attachments / folders / `@` / project `cwd`** — Implicit filesystem reach for CLI-backed models; no allowlist, path display, or “what will be readable” preview before send.
3. **Tool toggles in Context** — Web / Hermes / Tasks next to Files without tying UI to approval policy (12): toggles can read as always-on capability, not pending approval.
4. **History replay on model switch** — “Replayed as plain messages” may strip tool results or leak prior tool output into a weaker/other provider without a warning.
5. **API sketch** — `POST .../messages` with attachments and SSE; no auth, tenant, retention, or cancel auth on `POST /runs/:id/cancel`. Fine as a sketch; dangerous if treated as the contract.
6. **“Stored locally”** — Underspecifies encryption at rest, export, delete, and whether runs/logs leave the machine.

### UI / design-quality problems (hierarchy, spacing, type, density, motion, legibility, contrast)

**Hierarchy** — Center thread should own the screen; the doc gives equal billing to list, composer chrome, and Context. Per app screens: color on data, not chrome; ~3% colored pixels; quiet nav. Provider icons on every list row + model/effort/route headers + agent badges + tool cards will read as kit chrome unless one ink hierarchy is locked (identity + key meta only).

**Density** — Chat is a long-session, medium–dense feed. No row pitch for list (~44–56px medium) or message spacing. Risk: “generous spacing” mockup air with a sparse first viewport (empty thread + oversized composer) — judges call that thin.

**Typography** — No scale. Operate wants one grotesk, fixed rem steps (~12/14/16/24), not display. Message body measure for markdown/prose (65–75ch) and mono only for code/IDs — unspecified; stitch-world Inter + JetBrains everywhere would costume the UI.

**Composer control cluster** — Segmented Low/Medium/High/Max + model chip + attach in one bottom bar is classic over-chrome. On phone, stacked segmented controls push content down (app-screen phone rule). Prefer one primary control visible; effort secondary or inside model popover.

**Badges / pills / cards** — Agent badge, connection teal/grey, tool-call cards, thinking collapse: each needs “one status mark” and pale tint + dark text if chips exist. Spec invites saturated “Connected” teal and card-per-tool-call noise.

**Contrast / legibility** — “Greyed” effort; “Not connected” in grey; token estimate as secondary meta — all need ≥4.5:1. Disabled composers must explain why (acceptance mentions this once; no pattern for partial disable: model ok, tools blocked, over token limit).

**Motion** — Streaming and cancel need state feedback only (cursor/progress, cancel press). No shimmer-as-decoration, no orchestrated load. Collapsible thinking: height/opacity with `prefers-reduced-motion` — not specified.

**List selection** — Inbox pattern: selected row uses `--active` fill, not a focus-ring lookalike. Unspecified → hover/selected/focus confusion.

**Glass / accent inheritance** — Via “matches mockup,” this doc inherits a world (glass blur, electric violet, dark-first) that design-taste bans for app chrome. Either this spec must **override** mockup materials (opaque tone steps, accent on streaming/data only) or accept a permanent craft conflict with the skills you asked to apply.
