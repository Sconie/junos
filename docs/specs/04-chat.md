# Chat

## Purpose
The main place to talk to any connected model with a model and effort picker. Agent chats (Hermes etc.) live in the same component with an agent badge (see 07).

## Layout (matches mockup)
Left: conversation list (Today / This week / Older, search, New chat, provider icon each). Center: thread. Bottom: composer. Right (collapsible): Context panel.

## Features
**Composer**: multi-line, Enter to send, Shift+Enter newline, attach files or project folders, `/` commands, `@` to mention a file, project, or agent.
**Model picker**: popover grouped by provider with connection state; disabled providers show a Connect link. Remembers last choice per conversation.
**Effort picker**: segmented Low/Medium/High/Max, greyed where the model has no such level.
**Messages**: header shows model, effort and route ("Claude Opus, high, via subscription"); markdown, code blocks with copy, tables, collapsible thinking, tool-call cards, retry with another model, branch from this message, "send to Kanban", "save to file".
**Streaming** with cancel. Partial output is kept on cancel.
**Context panel**: attached files, selected project (sets `cwd` for CLI-backed models), tool toggles (Files, Web, Hermes, Tasks), token estimate.
**Compare mode** (phase 3): send one prompt to two models side by side.
**Slash commands**: `/model`, `/effort`, `/project`, `/task` (turn this into a scheduled task), `/card`, `/hermes <directive>`.

## Behavior rules
- Conversations are stored locally; each assistant message links to its run.
- Switching model mid-thread is allowed; history is replayed as plain messages.
- Tools: the daemon exposes a small tool set (read file, list projects, create card, create task) to models that support tool use, always behind the approval policy in 12.
- Titles are auto-generated by the cheapest connected model after the first exchange.

## API sketch
```
POST /conversations            {title?, projectId?}
POST /conversations/:id/messages  {content, model, effort, attachments[]} -> SSE of RunEvent
POST /runs/:id/cancel
GET  /conversations?cursor=
```

## Acceptance criteria (Phase 1)
- Send a message to Claude via subscription and see streamed output.
- Changing model/effort changes what is sent (visible in the run record).
- With the provider logged out, the picker shows Connect and the composer explains why it cannot send.

## Rev 2 additions
- **Allowed providers**: each conversation shows which providers may receive its context; switching model to a different provider, fallback, and auto-title generation respect that list, and the first time context goes to a new provider the composer shows a one-line disclosure.
- **Model switch**: shows what history is replayed and warns if attachments/tool results will be sent to the new provider.
- **Tool toggles** are requests, not permissions: every tool call goes through the gateway (12). Toggling Files on lets the model *ask* to read; it does not grant folder access beyond the project allowlist.
- **Attaching a project folder** attaches a manifest and on-demand reads within the allowlist, never the whole tree; size limits and `.junosignore` apply.
- Markdown, links and images render through the safe pipeline in 12.
- Enter in the composer only sends; ⌘K navigation never submits a prompt to a model without an explicit send.
